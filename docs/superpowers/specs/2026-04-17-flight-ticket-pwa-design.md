# 机票识别 PWA — 设计文档

**日期：** 2026-04-17  
**状态：** 已批准

---

## 概述

一个手机端 PWA 网页应用。用户上传两张往返机票购票页截图，应用通过 Tesseract.js 在浏览器内 OCR 识别，提取航班信息后展示可编辑确认界面，用户确认后生成固定格式的预订委托文字，一键复制。

---

## 技术栈

- 纯静态 HTML + CSS + JavaScript（无框架）
- Tesseract.js v5（WebAssembly，中文语言包，浏览器内运行，无服务器）
- 部署：Vercel（静态站点，免费，公网访问）

## 数据流

```
用户上传2张截图（去程 + 回程）
    → Tesseract.js OCR（浏览器内，约5-10秒/张）
    → 解析：从截图顶部标题提取城市名，正文提取航站楼、时间、航班号
    → 展示可编辑确认字段
    → 用户确认/修改
    → 按固定模板生成文字
    → 一键复制到剪贴板
```

## 界面与交互（三屏流程）

### 屏幕①：上传页

- 两个上传区域：「去程截图」「回程截图」
- 点击触发手机相册/文件选择器
- 两张都选好后「开始识别」按钮激活
- 识别中显示进度条

### 屏幕②：确认页

每程各显示 5 个可编辑输入框：

| 字段 | 示例值 |
|------|--------|
| 日期 | `4.28` |
| 出发机场 | `广州白云 T2` |
| 到达机场 | `徐州观音 T2` |
| 时间段 | `15：05-17：25` |
| 航班号 | `南航CZ3339`（航司+编号合并为一个字段） |

识别失败的字段留空，用户手动填入。点击「生成文字」进入下一屏。

### 屏幕③：结果页

- 展示生成的完整文字
- 「复制」按钮，点击后显示"已复制"提示
- 「重新开始」回到上传页

## OCR 解析逻辑

### 城市 + 机场字段

1. **优先**从截图顶部路线标题解析城市（如「广州 → 徐州」）
2. 从正文匹配航站楼名称（如「白云T2」「观音T2」）
3. 拼合为完整字段：`{城市}{机场名} {航站楼}`（如「广州白云 T2」）
4. 任意步骤失败则留空，用户手动填入

### 其他字段正则

| 字段 | 匹配目标 |
|------|---------|
| 日期 | `\d{1,2}[-./]\d{1,2}` 或「月日」格式 |
| 时间段 | `\d{2}[:：]\d{2}\s*[—\-–]+\s*\d{2}[:：]\d{2}` |
| 航班号（含航司） | 先匹配「南航」「长龙」等前缀，再匹配 `[A-Z]{2}\d{4,5}` 编号，拼合为「南航CZ3339」 |

## 输出模板（固定）

```
Dear Candy,
请帮忙预定以下往返机票，谢谢~

{去程日期}
{去程出发机场}-{去程到达机场}
{去程时间}
{去程航班号}

{回程日期}
{回程出发机场}-{回程到达机场}
{回程时间}
{回程航班号}
```

**示例输出：**
```
Dear Candy,
请帮忙预定以下往返机票，谢谢~

4.28
广州白云 T2-徐州观音 T2
15：05-17：25
南航CZ3339

4.30
徐州观音T2-广州白云T2
16：15-19：00
长龙GJ8060
```

## 错误处理

- OCR 超时（>30秒）：提示用户重试或手动填写
- 字段识别为空：输入框高亮提示，用户可直接填入
- 剪贴板不支持：展示文字供用户手动复制
